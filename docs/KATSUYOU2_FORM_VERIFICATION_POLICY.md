# 活用2：活用検証 → 例文作成の固定フロー

更新日: 2026-08-07

## 目的

今後は「規則で文字列を作れたから、そのまま例文を書く」という順番を禁止する。

必ず、**活用そのものを検証してから例文を作る**。

## 1動詞ごとの順番

1. 活用1の `ます・て・た・ない` を独立した正解データとして確認する。
2. Group 1 / 2 / 3 の判定と発展5形を生成する。
3. 活用検証担当が、各発展形を外部資料で確認する。
4. 各形を `valid` / `not_applicable` / `deferred` のどれかに決定する。
5. `valid` の形だけ例文チームへ渡す。
6. 例文チーム8担当が、日本語・英訳・初級適性・自然さ・場面の偏り・穴埋め問題としての成立を確認する。
7. 自動テストを通す。
8. mainへマージ後、Firestoreへ同期する。

## 判定ステータス

### `valid`
その動詞のその活用として、辞書・日本語教育資料・実際の使用のいずれかで十分な根拠がある。例文作成と出題が可能。

### `not_applicable`
その動詞の通常の活用として扱うべきでない。データは `null` とし、一覧では「該当なし」、クイズでは出題しない。

### `deferred`
機械的には生成できるが、根拠や初級教材としての適性がまだ不十分。例文を作らず、出題対象にも追加しない。追加調査後に `valid` または `not_applicable` へ変更する。

## 証拠の優先順位

1. 国立国語研究所、国際交流基金などの日本語教育・言語研究機関
2. 国語辞書・学習辞書・JMdict系辞書での活用情報
3. コーパス・実際のWeb用例
4. 標準的な活用規則
5. チーム内のネイティブ判断

規則だけを根拠に `valid` にしない。特に可能形・使役形は、別動詞との衝突、意味の変化、実際にはほとんど使われない形を確認する。

## 例文を作ってはいけない条件

- 検証ステータスが `not_applicable`
- 検証ステータスが `deferred`
- 検証レコードが存在しない（2026-08-07以降の新規 evidence-first batch）
- 辞書上は形があっても、例文にすると別語・別義としてしか自然に読めない
- 初級学習者に誤解を与える可能性が高い

## 記録先

- 検証結果: `data/katsuyou2/form-verification.json`
- 例文データ: `data/katsuyou2/part-*.json`
- 全体引き継ぎ: `PROJECT_CONTEXT.md`
- 役割定義: `AGENTS.md`

## 自動テスト

`verificationRequired: true` が付いた例文データは、以下をCIで必須確認する。

- `sourceVerbId` に対応する検証レコードがある
- 発展5形すべてに判定がある
- 例文がある形は `valid` である
- 検証値と本番データの活用形が一致する
- 日本語例文内に正解活用が実際に含まれる
- 日本語・英語の両方が存在する
- 証拠URLと確認日が記録されている

このテストを通らない新規例文batchはmainへ入れない。
